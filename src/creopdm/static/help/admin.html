How to administrate CreoPDM

Administration covers who can sign in, what each person can do, which products they can open, what state each product is in, and the server tools that keep it healthy. Start at Administration in the top bar.

Quick start

The Administration page is a set of tiles. Each tile appears only when your role has the matching permission.

Users

Add and edit accounts, assign a role, set status, set passwords.

Roles

Create roles and choose what each one can do — products, files, administration.

Manage products

Products, Product Membership, Copy, Promote, Lifecycle states, then Delete, Compact and Rebuild.

Utilities

Email all users, Audit log, Health and Logs.

System Settings

Server-wide options: Open Creo models, Vault, file types, the local agent, Database, Email, AI, Availability.

Two layers decide what a person can do. The role says what the person may do at all; the product’s lifecycle state says what is allowed on that product right now. A button appears only when both agree — “state ∩ role”.
Always keep at least one active user with every administration permission. CreoPDM refuses to remove the last one.

Users

Administration → Users lists every account.

  • Add a user: name, username, email, role, status and an initial password. The person must change a temporary password at first sign-in.
  • Status Active or Disabled. A disabled user cannot sign in; their history and audit entries stay.
  • Passwords are set or reset with the “Set or reset user passwords” permission. Email on the server lets people use Forgot password.
  • Role is assigned with the “Assign roles to users” permission.
  • Product access is set per user here or under Product Membership (All products, or a chosen list).

Roles & permissions

Administration → Roles creates roles and picks their permissions. Everything a signed-in person sees is checked against these keys on the server, not only by hiding buttons.

GroupPermissions
AdministrationManage users, set passwords, assign roles, manage roles, assign products (membership), manage products, manage lifecycle states, change settings, AI settings, email.
UtilitiesAvailability, Email all users, Compact, Rebuild, Delete products, Audit log, Health, Logs — each its own key.
ProductsView, create, edit, delete or forget, export a whole product.
FilesView, add, check out, check in, force undo checkout, remove, revert (restore an older version), revise, update metadata, copy to vault, export selected.
  • Starter roles are Administrator (everything), PDM Manager, Engineer (everyday authoring, including Revise) and Viewer (browse and open). They are only a starting point; edit or add roles freely.
  • Revise is its own permission, objects.revise. Give it to the people who may start the next revision of a released file.
  • A role that can see a file but not check it out simply never gets the checkout buttons.

Products

Administration → Manage products is the hub for everything about a product. Products lists every product on the server and lets you add or edit one.

Add a product

  1. Choose Add product and enter a Name (required, must be unique), an optional Number and Description.
  2. The Vault/Workspace name is the folder under the vaults directory. By default Use hash is ticked: a unique id is filled in and locked.
  3. Untick Use hash to type your own folder name (no spaces). It cannot be the same as another product’s vault name.
  4. The folder cannot be changed after the product is created.
  • Edit changes name, number and description. The product list shows the number under the name only when one is set.
  • Copy Products makes a new product from another product’s current vault files. Each file starts again at A.1, In Work, not checked out, with a fresh history.

Product Membership

Decide who can open which products, either by product (pick the people) or by user (pick the products).

  • A user with All products sees every product.
  • A user restricted to a list sees only those products, even if their role could otherwise open any.
  • Membership never grants more than the role allows; it only limits which products are visible.

Lifecycle states

Manage products → Lifecycle states is the permission matrix. Each row is a product state; each column is an operation that state allows (ticked) or blocks.

ColumnWhat it controls
Read / ViewSeeing the product and its files.
Download / Export / OpenOpening files in Creo, downloading and exporting.
Check Out / Undo CheckoutChecking out, and releasing your own or another user’s checkout.
Check In / Add / UploadCheck-in, adding files, uploads.
Delete / Remove (vault)Removing files from the vault.
Edit MetadataCollect, rebuild metadata and AI snapshots.
Revise (new revision)Offering Revise… for Released files.
Rename productChanging the product’s name.
View History / AuditHistory tabs and audit views.
  • Defaults: Pre-Work and In Work are editable, In Review and Approved are frozen, Released is frozen, Under Change is editable again, Obsolete, Archived and Locked are frozen.
  • Revise is allowed in In Work and Under Change by default, and off in Pre-Work and in every frozen state.
  • You can add your own states, reorder them and rename labels. Built-in states cannot be removed.
  • Changes take effect for everyone as soon as you save.

Promote Products

Manage products → Promote Products changes one product’s lifecycle state. You confirm with your password.

Releasing

Moving a product to Released also marks its files Released. Files already Obsolete stay Obsolete. This is what makes Revise available later.

Checked-out files

Promoting to Released, In Review or Approved is refused while any file is checked out; the message names the files and who holds them. Check them in or undo the checkout first.

Going back

Moving a product back to Under Change or In Work leaves its files Released. Each one needs a Revise before it can be edited.

Undo a release

When promoting to In Work or Pre-Work a product that has Released files, tick Also set the N Released files back to In Work (undo the release) to unlock them without Revise — for example after a release by mistake. Files already In Work are untouched.

The audit shows each promote as Product state changed, with how many files were released or set back to In Work.

Revise (admin view)

Users start the next revision of a Released file with Revise… (A.3 → B.1). As administrator you control who and when:

  • Who: the objects.revise permission on the role.
  • When: the product’s state must allow Revise in the Lifecycle states matrix (In Work and Under Change by default), the file must be Released, and nobody may have it checked out.
  • Reopening a released product for revision: promote it to Under Change. A product that is itself Released is frozen and does not offer Revise.
A user says they cannot see Revise? Check in this order: the file reads Released · it is not checked out · their role has Revise · the product’s state allows Revise · the page was reloaded after a deploy.

Each revise is recorded in the Audit log as Revision created (A.3 → B.1, with the reason). The new revision keeps its own metadata; the released one is never changed, and baselines and product releases keep pointing at the version they used.

Delete, compact, rebuild

These sit under Manage products, in red, and each needs its own Utilities permission and your password.

ActionWhat it does
Delete productsDeletes the product’s vault and unregisters it from the database. History in the Audit log is kept.
Compact product vault historySquashes one product’s Git history to the tip and frees the bytes of removed files. Older versions are no longer restorable.
Rebuild product databaseRebuilds a product’s database records from its vault, with options for metadata and the Where Used index.
Take a copy of the vault folder before compacting or deleting anything you may need again. Neither can be undone from CreoPDM.

Utilities

Administration → Utilities holds day-to-day server tools. Each tile needs its own permission.

  • Email all users sends one message to every active user; addresses stay private.
  • Audit log — see below.
  • Health shows CPU load, I/O, disk space, the database, Git, product vault checks, counts and server paths. Look here first when something is slow.
  • Logs lists the server log files and shows the end of the selected one (default creopdm.log).

Audit log

Utilities → Audit log records what happened, who did it, from which client and to which product and file. Filter by event, user, product or text.

  • Check in / Check out, Object added or removed, Checkout cancelled or overridden.
  • Revision created (A.3 → B.1, with the reason) and Version restored (for example Restored A.1 as D.3).
  • Changes discarded when someone throws away unsaved vault changes.
  • Product state changed with “N files released” or “N files set back to In Work”.
  • Sign-in, password, role, membership and system-setting changes.
Audit entries are append-only. Deleting a product keeps its history rows.

Troubleshooting

A delete or rebuild fails with “unexpected error”

Open Utilities → Logs, select creopdm.log and read the last lines — the real cause is there. Send the error text when asking for help.

A user cannot check out or check in

Check the product’s state in the Lifecycle matrix (Check Out and Check In columns) and the role’s permission. A Released file also cannot be checked out until it is revised.

A checkout is stuck

Use Force Undo Checkout (permission required) in a state that allows Check Out. In a frozen state, promote the product to Under Change or In Work first.

A file keeps reading Modified

Right-click it → Discard changes… (also on its row on the Modified tab). It restores the vault copy and, for a Newer local save, removes the local file from that PC. It needs no checkout to be held.

Menus look old after an update

Reload the page; if a menu item is still missing, hard refresh (Ctrl+F5). The server serves its scripts fresh, but browsers cache some files.

Creo: Agent offline

The agent tray is not running on that PC. Collect metadata, Rebuild metadata and Open refuse to run without it. See the user help for starting it.

Before you change something big

  1. Mark the site Unavailable (System Settings → Availability) and email users from Utilities.
  2. Make sure nothing is checked out (Checked out tab on each product).
  3. Check Utilities → Health for disk space and the database.
  4. Make the change, then turn Availability back on.
