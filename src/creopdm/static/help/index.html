How to use CreoPDM

CreoPDM keeps your product files in a shared vault, lets you check out work to edit, and records every check-in with history. This page covers the day-to-day Files workflow.

Start here Agent tray Toolkit Checkout → Check In Revise Open assemblies If something fails

Quick start

A typical edit cycle takes a few minutes once you know the toolbar.

  1. On a Creo PC, start creopdm-agent-tray (see Agent tray), load the Toolkit Companion in Creo, and open CreoPDM in Creo’s built-in browser.
  2. Pick a product in the left sidebar.
  3. Checkout the file (or files) you will change.
  4. Open the model in Creo and save your edits.
  5. Use Check In, write a short comment, and finish.
  6. The list updates on its own — you should not need to press F5.

What stays shared

The vault holds the product’s official files and history. Everyone on the product sees those versions after check-in.

What is yours locally

Your workspace on the Creo PC holds working copies. Checkout locks a file so others cannot edit it at the same time.

Product state matters. Lifecycle permissions are configured under Administration → Lifecycle states. By default, Pre-Work / In Work / Under Change allow edits; Locked is list-only (no Checkout, Undo, Open, or download). New products start as In Work.

Agent tray

CreoPDM’s server holds the shared vault. On your Windows Creo PC you also need creopdm-agent-tray — a small app in the system tray that downloads and uploads CAD for Open, Checkout, Add, and the local workspace.

How to open the install help

  1. Sign in to CreoPDM inside Creo’s built-in browser (Embedded open mode).
  2. If Creo.JS is linked but the tray is not running, the top-bar pill shows Creo: Agent offline.
  3. Click that pill — it opens a short page to start an existing tray, download creopdm-agent-tray.exe from this server (when your admin published it), and set Windows Startup so it launches at sign-in.

You can also open that page anytime at /help/agent-tray.

First-time download

From the Agent offline page, use Download creopdm-agent-tray.exe. Save it somewhere stable (for example under %LOCALAPPDATA%\CreoPDM-agent\), then double-click to start. A tray icon appears near the clock (check the overflow ^ if needed).

Autostart

Press Win+R, run shell:startup, and put a shortcut to the exe in that folder so the tray starts when you sign in to Windows.

Using the tray

Right-click the tray icon:

  • Show status — port, version, cache folder
  • Show logs — live log (also %LOCALAPPDATA%\CreoPDM-agent\logs\agent.log)
  • Open cache folder — local product workspaces (%LOCALAPPDATA%\CreoPDM-agent\workspaces)
  • Quit — stop the agent (CreoPDM will show Agent offline until you start it again)

Quick check: open http://127.0.0.1:8766/health on this PC — it should respond when the tray is up. The pill should read Creo: Connected in Creo’s browser when both Creo.JS and the agent are healthy.

Run the tray on the Windows Creo PC, not on the Linux CreoPDM host. If Download is missing or fails, ask an administrator to publish the exe (install README → downloads/creopdm-agent-tray.exe). Collect and Modifications also need the Toolkit Companion loaded inside Creo.

Toolkit Companion

CreoPDM Toolkit Companion is a small Creo auxiliary app (Pro/TOOLKIT). It runs inside Creo and answers on http://127.0.0.1:8767. The agent tray calls it when CreoPDM needs model data. It is required on every Creo PC that will Collect metadata. Source and the prebuilt DLL: github.com/mbourque/CreoPDM-Toolkit-Companion.

What it is used for

  • Collect and gear Rebuild metadata — identity, parameters, features, structure, BOM, mass, drawings, and manufacturing data.
  • Details tabs that show that collected data (Features, Structure, Parameters, and the rest).
  • Modifications — the NEW side disk-retrieves the local workspace tip (for example shaft.asm.3). The model does not need a window open. Creo must be running with the companion loaded, and the agent tray must be up.

Windows x64, Creo Parametric 10 and later. A Toolkit app cannot run by itself — Creo has to be open. It listens on this PC only and does not open a Creo window to collect.

Install

  1. Download the repo (Code → Download ZIP, or git clone https://github.com/mbourque/CreoPDM-Toolkit-Companion.git). A prebuilt unlocked bin\creopdm_structure.dll is included.
  2. Keep these three together in a permanent folder, outside Creo’s install directory. Example C:\CreoPDM\Toolkit\: protk.dat, bin\creopdm_structure.dll, and text\usascii\creopdm_msg.txt.
  3. Edit protk.dat so the paths match that folder (the copy in the repo has the author’s paths and must be changed): 
    NAME        CreoPDMStructure
EXEC_FILE   C:\CreoPDM\Toolkit\bin\creopdm_structure.dll
TEXT_DIR    C:\CreoPDM\Toolkit\text
STARTUP     dll
ALLOW_STOP  TRUE
REVISION    18
END
    Leave REVISION 18 unless Creo reports a revision problem.
  4. Add one line to a config.pro Creo reads at startup (your startup folder, or <Creo install>\Common Files\text\config.pro for everyone on the machine): 
    protkdat C:\CreoPDM\Toolkit\protk.dat
    Creo accepts several protkdat lines if you already load other Toolkit apps.
  5. Restart Creo. config.pro is only read at startup. Close Creo before you replace the DLL later — Creo locks the file while it is loaded.

Check that it loaded

On startup the Creo message line should say CreoPDM Structure: HTTP listening on 127.0.0.1. The app also appears in Creo’s Auxiliary Applications list. With Creo running, in PowerShell: 

Invoke-RestMethod http://127.0.0.1:8767/health

Expect ok: true and service: creopdm-toolkit. Log: %TEMP%\creopdm_toolkit.log.

How CreoPDM uses it

Start the agent tray and Creo (with the companion loaded), then work in Creo’s browser. Collect does not call Toolkit from the browser or from the Linux server. The page asks the agent (127.0.0.1:8766); the agent asks Toolkit (127.0.0.1:8767). Toolkit retrieves the workspace file into memory when it is not already in session — no new window or tab.

Optional ribbon command: File → Options → Customize Ribbon → All Commands → CreoPDM Structure Export. The HTTP service does not need that button.

If it does not start

What you seeWhat to do
“was not unlocked before distribution” or startup failed Use the prebuilt DLL from the repo, or unlock a rebuild (see the companion README). Check EXEC_FILE in protk.dat.
No message line at startup Check the protkdat path, EXEC_FILE / TEXT_DIR, and that you edited a config.pro Creo actually reads. Restart Creo.
Message line says HTTP was not started Port 8767 is already in use. Set CREOPDM_TOOLKIT_PORT before Creo starts, and point the agent at that URL if it is not 8767. See the log.
Collect or Modifications says Toolkit is offline Creo must be running with the companion loaded, and the agent tray must be running. /health on port 8767 should answer before you Collect.
Full API, build-from-source, and domain notes are in the companion README. You only need to build if you change that code. The published DLL is already unlocked.

The Files list

Most work happens on the product Files page: a breadcrumb path, metric filters, Search, list tabs, and the bottom toolbar.

List tabs

TabWhat you see
FilesNormal folder view for the current path. Search is available here.
Checked outFiles currently locked for edit.
ModifiedVault files with newer local or vault saves ready to check in.
New filesFiles waiting to be added to the product (not yet in the vault as product objects).

Finding things

  • Search (Files tab) matches names, paths, revisions, Type labels, and more. Wildcards like *.prt work.
  • Metric pills (Parts, Assemblies, Drawings, Modified, Folders, Top level assemblies, …) filter and select matching rows. Click again to clear.
  • Column headers sort the list; click again to reverse.
After you open Details and press Back, CreoPDM keeps your search text, selection, and which list tab you were on.

Folders & selection

Folder rows and file rows use different click rules so you can open or select without surprises.

You clickWhat happens
Folder name (icon + name)Opens that folder.
Elsewhere on the folder rowSelects the folder (for Remove, Export, and so on).
File name / rowSelects the file. Double-click opens Details / History.

Empty folders stay selectable and removable — you do not need a file inside them first.

Add files

Use Add ▾ when something new should become part of the product.

  • Add selected… — promote New files from the list into the product.
  • Add files… / Add folder… / Add folders… — pick from disk (creopdm-agent helps on the Creo PC).
  • Compressed data… — import a zip into the product.
  • Create folder… — make an empty folder in the current location.
Large adds show a busy overlay (Where Used indexing, then metadata when Creo is Connected). Wait for it to finish — the list refreshes when the work is done.

Open in Creo

Open brings the model (and the companions Creo needs) into your local workspace, then launches it.

If the file is not checked out to you

  • Open without checking out — view / reference; no edit lock.
  • Check out this file, then open — lock only this file.
  • Check out this file and its dependencies, then open — lock the full tree Creo needs.

Viewers (and anyone who cannot checkout) skip the dialog and open immediately.

Large assemblies can take a while. CreoPDM finds dependencies, downloads missing tips, then waits for Creo to finish Retrieve. Watch the busy messages; do not assume the session is offline just because a big open is still running.
  • Prefer Creo’s embedded browser when using Embedded open mode.
  • Set Working Directory is optional and Creo-only — leave it off unless you need it.
  • If Open seems to do nothing, check the error line under the toolbar and that creopdm-agent is running on the Creo PC.

Checkout

Checkout locks files for you and downloads them for editing under logical tip names (for example shaft.prt), keeping vault folder paths in your workspace.

Checkout selected

Locks the files you selected. Will not take a file someone else already has checked out.

Checkout product

Locks everything that is free in the product. Handy for broad edits; still respects other people’s locks.

Undo Checkout

Releases your locks without creating a new version. Does not delete vault files, and a save you already made is kept so it can still be checked in. Hidden when the lifecycle matrix blocks Check Out (for example Locked or In Review).

Discard changes…

For a file that keeps reading Modified after you no longer want the change. Right-click the file (or its row on the Modified tab) → Discard changes…. A save staged in the vault is thrown away and the file goes back to its checked-in version; a Newer local save (for example shaft.prt.2) moves to the Recycle Bin on this PC. No new version is created. If someone has the file checked out, undo that checkout first.

Force Undo Checkout

Releases another user’s abandoned lock (permission required). Confirms first; may email that user. Same matrix Check Out rule as Undo.

Check In

Check In records a new version in the vault and releases the lock when the work is saved.

  1. Open Check In ▾ → Check in selected… or Check in product….
  2. Confirm the local tip shown in the dialog (for example shaft.prt.2). The vault stores the logical tip (shaft.prt).
  3. Enter a comment — blank comments are blocked.
  4. Optional in Creo when AI is enabled: Ask AI for comment drafts a summary you can edit.
  5. Finish — the list and statuses update to match the vault.
New files (not yet in the product) are added with Add ▾ → Add selected…, not Check In. Check In is for modified vault tips and related pending saves.

Revise

Revise starts the next engineering revision of a file that has been released — for example A.3 → B.1 — without touching the released one. It is the only way to edit a Released file.

Revise vs Check In

Check In keeps the revision and moves the iteration (A.1 → A.2 → A.3). Revise moves to the next revision and restarts at iteration 1 (A.3 → B.1). They are separate actions.

What you get

The same file gets a new version, B.1, In Work, that starts from the released content with its own copy of the metadata. The released version stays Released, unchanged. Then you check B.1 out, edit it and check in to get B.2.

When Revise is available

You see Revise… only when all of these are true:

  • The file is Released (releasing a product releases its files).
  • Nobody has the file checked out.
  • You have the Revise permission (Engineers, PDM Managers and Administrators by default).
  • The product’s state allows it — In Work and Under Change by default. A product that is itself Released is frozen: reopen it first (Under Change is meant for this).
Not seeing it? Right-click the file: if Revise… is missing, check that the file reads Released, that it is not checked out, and what state the product is in (shown next to the product name).

How to revise a file

  1. Right-click the Released file → Revise… (also a Revise… button on the file’s Details page).
  2. The dialog shows the file, the source version (for example A.3), the new version (B.1, chosen by the server) and that the new version starts In Work at iteration 1.
  3. Enter a Revision Reason — required. It is saved with the revision and the audit trail.
  4. On the Files list you can tick Check out B.1 after creating it to go straight to editing.
  5. Press Create Revision B. The list refreshes and shows the new revision.

After a revise

  • History on Details is grouped by revision, newest first (Revision B above Revision A), and the released versions are marked Released.
  • Overview shows Created From (for example A.3) and the Revision Reason.
  • The audit trail has a Revision created entry (A.3 → B.1, with the reason).
  • Baselines, product releases and Where Used keep pointing at the version they used — a new revision never rewrites them.

Good to know

  • The server chooses the revision (A → B → C … Z → AA). It cannot be typed in.
  • Safe to retry. If the answer is lost, press Create again — you get the same B.1, never a second revision.
  • Unchanged-file note. If a released revision is identical to the version it started from, the dialog adds a note (“has not changed since A.1”). You can still go ahead.
  • All or nothing: if anything fails, no revision is created.
  • Revise is not Save As (that would be a new file name) and Creo’s numbered saves (shaft.prt.2) are not revisions.

Releasing and reopening a product

  • Moving a product to Released releases its files. It is refused while any file is checked out (so is In Review and Approved) — check the files in or undo the checkout first.
  • Moving the product back to Under Change or In Work leaves its files Released; each one needs a Revise before it can be edited.
  • Administrators can choose Also set the Released files back to In Work (undo the release) when promoting to In Work or Pre-Work, for example after a release by mistake.

Baselines

A baseline is an exact, frozen snapshot of a product: the version of every file at the moment you create it. Use it for a design review, a customer build or any configuration you must be able to name again later.

It never changes

Check-ins and new revisions do not alter a baseline. If shaft.prt was A.2 when you created it, the baseline still says A.2 after A.3 or B.1 exist.

It keeps its versions

While a baseline holds a file, Remove from Product is refused, and so are Compact vault history and Rebuild file list. The message names the baselines.

Create a baseline

  1. Open the product and choose the Baselines tab (or click the N Baselines chip).
  2. Choose Create Baseline…. You need the Create baseline permission; everyone with access can view the list.
  3. Enter a name (unique in the product) and an optional description, then Create Baseline.
  4. It appears in the list as Finalized with how many files it holds.
  5. Click its name to see the exact version of every file it captured, and whether the product still has that version or a newer one.
  6. A finalized baseline never changes: files can't be added, removed or swapped for another version. For a different configuration, create a new baseline.
  7. Checking a file in later never alters an existing baseline: it keeps the version it captured, and its contents show that the product now has a newer one.
A baseline records each file’s last checked-in version. A file that is checked out or modified on your PC is captured as it was before your edits.

Remove & cleanup

Use Remove ▾ carefully — some actions only clean your PC; others change the shared product.

ActionAffects
Remove from Workspace…Local copies on this PC only (new files, or a Newer local save row on the Modified tab). Vault unchanged.
Purge workspace…Older local numbered saves below the vault tip. Vault unchanged.
Clear workspace…Everything inside this product’s local workspace folder. Vault unchanged.
Remove from Vault…Deletes CreoPDM vault copies. Your original CAD folders on disk are not the same thing.
Remove from Product…Removes from the product and deletes vault copies. Confirms with your password.
Destructive vault / product removes ask you to re-enter your password. Cancel if you are unsure — originals outside CreoPDM’s vault are not a substitute for a careful confirm.

Watch & email

When email notifications are enabled on the server, a bell appears next to the product gear.

  • Watch this product to get email summaries for adds, removes, checkout, undo checkout, check-in, restore, and product info changes.
  • Check-in emails include the check-in comment.
  • You are not emailed for your own actions.
  • Watching is per user — someone else’s Watch does not make you a watcher.

Details, history & modifications

Open a file’s Details (toolbar or double-click) for overview information, history, and (when available) Creo structure and AI compare tools.

  • History lists versions and check-in comments, grouped by revision (newest first). Restore / revert needs the matching permission; a restore is recorded as a new version and the audit says which version it came from (for example Restored A.1 as D.3).
  • Revision created by Revise shows Created From and the Revision Reason on Overview.
  • Modifications compares checked-in snapshots and, when the file is modified, a live gather of the current model.
  • Ask AI what changed uses the prompt saved under System Settings → AI (when enabled).
Export ▾ can zip the whole product or the current selection (files and folders). Confirm, wait for the busy overlay, then save the zip.

Tips & troubleshooting

Creo stays Connected

Moving around inside CreoPDM should not hard-reload the shell. If the pill flips to Session offline while you are still in Creo’s browser, try soft-navigating again or reopen Creo’s browser tab.

Busy overlay & Escape

Add, Check In, and Open keep the busy overlay until finished. Escape cancels only jobs that say they can stop (for example Rebuild Where Used / Collect metadata).

creopdm-agent

Local workspace pickers, downloads, and many Open paths need the agent on the Creo PC. See Agent tray — or click Creo: Agent offline in the top bar when it appears.

Who can do what

Menus follow your role. Viewers browse and open; Engineers edit; PDM Managers / Administrators get extra product and server tools under Administration.

Short checklist when Open fails

  1. Read the red/error line under the toolbar.
  2. Confirm creopdm-agent is running.
  3. For Embedded mode, use Creo’s built-in browser.
  4. For huge assemblies, give Retrieve more time before retrying.
